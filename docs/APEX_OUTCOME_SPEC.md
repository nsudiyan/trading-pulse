# Согласованные требования к расчёту результата сигналов (Apex)

Дата: 09.11.2026. Источник: ответ владельца проекта. Это **требования к поведению**, а не утверждение, что текущий код им соответствует.

## 1. Что считать отработавшим сигналом

- Подтверждённый сигнал = заранее зафиксированы **ТВХ, SL и TP**.
- **Победа** — цель достигнута раньше стопа.
- **Убыток** — стоп достигнут раньше цели.
- «Цена когда-то дала +2%» — это отдельная метрика **максимального движения после сигнала (MFE)**, а не win.
- Для наблюдения без подтверждённого входа показывается только движение цены, **без метки win**.

## 2. Что делать после стопа

- Стоп **завершает** модельную сделку.
- Если после стопа цена дошла до цели — результат остаётся **убыточным**.
- Новый вход после стопа — только как **отдельное подтверждённое событие** (новый ID).
- Если одна свеча коснулась и SL, и TP, а порядок неизвестен → результат **«неоднозначно»** (ambiguous), до появления более подробных данных (меньший таймфрейм).

## 3. Таймфреймы

- Бот анализирует закрытия: **15m, 1H, 4H, 1D, 1W**.
- Интрадей: 1D задаёт направление → 4H задаёт рабочую зону → 15m/1H подтверждают вход.
- Индикатор может уточнять ситуацию на 5m.
- Индикатор **не считается** точной копией Python-бота: совпадение алгоритмов подлежит отдельной проверке.

## 4. Сигналы и сделки в день

- Цель по строгим (подтверждённым) алертам: **0–2 в день**; фактическое количество — из БД.
- Обычные наблюдения (без подтверждённого входа) считаются **отдельно**.
- Уведомление в Telegram **не означает** открытие позиции.

## 5. Один сигнал — сколько результатов

- Один подтверждённый вход = **одна модельная сделка** с неизменным ID.
- Повторные уведомления **не создают** новые сделки.
- Повторный вход после стопа = новое событие, новая сделка.
- Цены через **1 / 4 / 24 / 72 часа**, максимальный рост и максимальное падение — **дополнительные показатели этого сигнала**, а не дополнительные победы.

## Главный критерий проверки дашборда

Дашборд **не должен** закрашивать результат зелёным только потому, что после сигнала когда-либо был рост.
Для шорта направление обратное; **срабатывание стопа учитывается раньше любого последующего движения**.

## Следствия для модели данных (предложение)

Минимальный набор полей у подтверждённой сделки:
`signal_id`, `entry_id`, `tf`, `direction`, `entry`, `sl`, `tp`, `opened_at`, `closed_at`,
`first_touch` ∈ {target, stop, liquidation, timeout, ambiguous, pending},
`outcome` ∈ {win, loss, ambiguous, pending},
`mfe_pct`, `mae_pct`, `post_target_max_dd_pct` (откат после достижения цели),
`price_1h/4h/24h/72h`, `bars_to_first_touch`.

Производные метрики:
- «Доля сигналов, у которых MFE ≥ +2% **до** стопа» — честный показатель качества сигналов.
- «Доля ложных win» = outcome=win при first_touch=stop → должна быть 0 по требованиям.
- «Средний откат после цели» = post_target_max_dd.
