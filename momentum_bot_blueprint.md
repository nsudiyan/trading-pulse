# Momentum-бот для DEX-токенов: архитектура, экономика, roadmap

**Дата:** 2026-06-09
**Статус:** design doc / research. НЕ статус проекта (статус — только в STATE.md).
**Вводные от пользователя:** капитал $500–2k · все стадии жизни токена · режим «только алерты» (исполнение руками через терминал).

Все конкретные пороги в документе — **стартовые эвристики для калибровки**, не проверенные константы. Цифры из внешних источников помечены ссылками. Оценки помечены ⚠️.

---

## 0. Главные выводы (TL;DR)

1. **Экономика жанра против вас.** По on-chain исследованиям (Dune/Galaxy, 2025–2026): ~60% трейдеров мемкоинов в минусе, ~90% в минусе или с профитом <$100, <3% сделали >$1000 на pump.fun. Зарабатывают платформы: BullX собрал $2.29B комиссий к началу 2026. Единственная группа со стабильным edge — снайпер-боты первых блоков (~87% прибыльных сделок по одному исследованию), и это latency-гонка, в которую с алерт-режимом и $1k входить нельзя.
2. **Следствие для дизайна:** ваш жанр — НЕ снайпинг первых минут, а **momentum на токенах, переживших первичный отсев**, где сигнал живёт минуты–часы и человек успевает исполнить руками. Все стадии покрываем, но S0 — только в режиме «наблюдение и сбор данных», не торговых алертов.
3. **Капитал $500–2k диктует:** позиции $100–250, пулы от ~$30–50k ликвидности, сети с копеечными комиссиями (Solana, BSC; ETH mainnet исключён), издержки за круг 4–8% оборота → сделки с целью <+25% нерентабельны.
4. **Алерт-режим — правильный выбор для старта:** убирает MEV-инженерию, кастодиальные риски и latency-гонку. Критичные требования смещаются на качество фильтра (security gate) и скорость доставки алерта (цель ≤10 сек от события).
5. **Главный актив бота — собственный размеченный датасет исходов.** Готовой чистой истории по молодым токенам (включая мёртвые) почти нет; сбор данных начинается с дня 1, торговля — с недели ~8. Бэктест обязан быть без survivorship bias и без look-ahead (path-resolution; урок short_dist в текущем скринере).

## 1. Детекция сигналов и фильтрация активов

### 1.1 Стадийная модель пайплайна

Один порог на все стадии не работает — базовые уровни объёма, волатильности и скам-плотности различаются на порядок. Три стадии:

| Стадия | Возраст | Роль в системе | Скам-плотность |
|---|---|---|---|
| **S0 fresh** | <48ч | Только наблюдение + сбор данных. Торговых алертов нет | Экстремальная: на pump.fun «выпускается» (graduation) лишь ~0.5–1.15% токенов; остальные умирают на bonding curve |
| **S1 survivor** | 2–30 дней | **Основной торговый фокус.** Прошли первичный отсев, rug-риск ниже, momentum-события частые | Высокая, но фильтруемая |
| **S2 mature** | >30 дней, mcap >$1M | Вторичный фокус: momentum continuation, breakout из консолидации | Умеренная |

### 1.2 On-chain метрики качества актива

Формат: метрика → hard reject / warn (штраф в скор). Пороги — стартовые, калибровать на собственных исходах.

**Концентрация холдеров** (источники: Moralis Token Holders API, RugCheck, GMGN):

| Метрика | Hard reject (S1) | Warn |
|---|---|---|
| Top-10 холдеров (исключая LP, CEX, burn) | >35% supply | >25% |
| Dev/creator кошелёк + связанные | >10% | >5% |
| Snipers hold rate (купившие в первые блоки; метрика GMGN) | >30% | >15% |
| Bundler rate (бандл-покупки одним оператором; метрика GMGN) | >25% | >10% |
| Insider ratio (GMGN «rat traders») | >20% | >10% |
| Доля fresh-кошельков (<7 дней) среди топ-50 холдеров | >60% | >40% |

Динамические метрики (важнее статических):
- **Рост уникальных холдеров**: устойчивый прирост день-к-дню = органика; плато при растущем объёме = wash trading.
- **Кластерный анализ** (Bubblemaps): связанные трансферами кошельки считать одним холдером. У Bubblemaps есть API с decentralization score (условия доступа проверить ⚠️); для ручного чек-листа в алерте достаточно ссылки на карту.

**Ликвидность / lock-unlock:**
- Solana: для pump.fun-выпускников LP сжигается автоматически после миграции на PumpSwap (нативный AMM pump.fun, запущен в 2025) — структурный плюс стадии S1 на Solana. Для прочих пулов (Raydium и др.) — проверять burn/lock через RugCheck.
- EVM: lock через UNCX (Unicrypt) / Team Finance / PinkLock. Требование: locked/burned ≥90% LP, остаток lock ≥30 дней. **Unlock-дата — событие в календаре бота**: предупреждение за 48ч по открытой позиции.
- Стабильность ликвидности: liquidity сейчас vs 24ч назад; падение >30% без сопоставимого падения цены = тихий вывод → reject.

**Контракт / права владельца:**
- Solana (SPL): mint authority revoked И freeze authority revoked — обязательные условия. Token-2022 extensions (transfer hooks, transfer fees) — по умолчанию reject, если hook/fee активен.
- EVM (флаги GoPlus token_security): honeypot → reject; mint-функция у owner → reject; blacklist/whitelist → reject; proxy/upgradeable → reject для S0/S1 (для крупных S2 допустимо с warn); pausable trading → reject; buy+sell tax >10% → reject; изменяемый tax → reject; owner not renounced → warn (в комбинации с mint/blacklist — reject); неверифицированный исходник → reject.

### 1.3 Off-chain детекция импульса

Триггер сигнала — конъюнкция (И, не ИЛИ) объёмной и ценовой аномалии; остальное — подтверждения и штрафы.

**Volume anomaly (главный триггер):**
```
baseline: rolling median и MAD объёма 5m-окон за 24ч этой же пары
vol_z = (vol_5m - median) / (1.4826 * MAD)        # робастный z-score
trigger_volume = vol_z >= 4
                 AND vol_15m >= floor(stage)       # абсолютный пол:
                 # S1: >= $15-30k за 15м; S2: >= $50-100k
                 AND net_buy_ratio_15m >= 0.60     # buys/(buys+sells) по объёму
```
Медиана+MAD вместо mean+std — обязательно: распределение объёмов мемкоинов фэт-тейловое, обычный z-score «ослепляется» одним старым спайком.

**Price velocity / acceleration:**
```
roc_5m  = close/close[-1] - 1
roc_15m = close/close[-3] - 1
accel   = roc_5m(t) - roc_5m(t-1)
trigger_price = roc_15m >= +8..15% (S1) / +5..8% (S2)
                AND accel > 0                       # импульс ещё разгоняется
                AND close > max(high, lookback=4h)  # пробой локальной структуры
```
Вход на затухающем ускорении (accel < 0 два окна подряд) — уже не ранняя стадия; скор режется.

**Участники (анти-wash, ключевой фильтр):**
```
buyers_15m >= 3 * avg(buyers_15m, 24h)  AND  buyers_15m >= 30..50 уникальных
доля кошельков с историей >7 дней среди новых покупателей >= 50%
распределение размеров покупок ~ power law (много мелких, мало крупных);
однородные размеры (все ~$200) = боты → reject
```

**On-chain аналог CVD:** net inflow (buy_vol − sell_vol) растёт ≥3 окна по 5м подряд. Прямой аналог CVD из текущего скринера, но по DEX-трейдам.

**Социальный сентимент — подтверждение, НЕ триггер:**
- Telegram: переиспользовать существующий `channel_reader.py` — частота упоминаний тикера/CA в мониторимых каналах; всплеск ≥5× от базовой частоты = +вес в скор. Упоминание ДО ценового движения ценнее упоминания после (после — это толпа, в которую продают).
- X/Twitter: прямой API дорог; практичный прокси — LunarCrush API (social volume, Galaxy Score, AltRank; есть бесплатный стартовый тариф). Для микро-токенов S0/S1 покрытие LunarCrush слабое ⚠️ — для них Telegram-сигнал важнее.
- Жёсткое правило: social-спайк без on-chain подтверждения = алерт не выдаётся (классическая схема «шиллинг → exit liquidity»).

### 1.4 Security scoring — сводный гейт

Двухступенчатый: **автоматический гейт** (hard reject) → **скоринг** (мягкие штрафы) → **ручной чек-лист в алерте** (то, что автоматике даётся плохо).

| Проверка | Solana | EVM (BSC/Base/ETH) |
|---|---|---|
| Комплексный риск-скор | RugCheck API (скор 0–100; read-эндпоинты без ключа) | GoPlus token_security |
| Honeypot-симуляция sell | косвенно: RugCheck + Jupiter quote на обратный своп (quote на продажу не строится/абсурден → красный флаг) | honeypot.is API (симулирует buy+sell); дублировать флагом GoPlus |
| Холдеры/инсайдеры | GMGN (insider/bundler/sniper/dev%), Moralis | GoPlus + Moralis Token Holders |
| LP lock | RugCheck (LP burned/locked) | GoPlus (lp_holders, lock-инфо) |

```
def security_gate(token, stage):
    f = fetch_flags(token)                 # GoPlus/RugCheck/honeypot.is/GMGN
    # -- hard rejects --
    if f.honeypot or f.cant_sell_sim:            return REJECT
    if f.mint_active or f.freeze_active:         return REJECT   # Solana
    if f.blacklist_fn or f.pausable or f.proxy:  return REJECT   # EVM, S0/S1
    if f.tax_total > 0.10 or f.tax_modifiable:   return REJECT
    if f.lp_locked_or_burned < 0.90:             return REJECT
    if f.top10_pct > stage.top10_max:            return REJECT
    if f.sniper_hold > 0.30 or f.bundler > 0.25: return REJECT
    # -- soft penalties --
    pen  = w1*scale(f.top10_pct) + w2*scale(f.dev_pct) \
         + w3*scale(f.insider)   + w4*(not f.renounced) + ...
    return PASS, pen
```

Практическое замечание: **источники регулярно расходятся** (GoPlus может не видеть кастомный honeypot, RugCheck-скор шумит на свежих токенах). Правило: любой единичный reject-флаг любого источника = reject; «чисто» = чисто по ВСЕМ. Цена пропущенного скама на порядок выше цены пропущенной сделки.

## 2. Техническая архитектура

### 2.1 Контур данных: три уровня

```
┌─ DISCOVERY (все кандидаты) ──────────────────────────────────┐
│ DEX Screener REST: token-profiles, boosts, search, new pairs │
│ polling 30–60 сек · бесплатно · 60–300 req/min               │
└──────────────┬───────────────────────────────────────────────┘
               ▼ кандидат (объём/возраст/ликвидность пол пройден)
┌─ ENRICHMENT (разовая проверка) ──────────────────────────────┐
│ RugCheck / GoPlus / honeypot.is → security gate              │
│ Moralis holders · GMGN-метрики · Birdeye OHLCV-история       │
└──────────────┬───────────────────────────────────────────────┘
               ▼ прошёл гейт → hot list (20–50 токенов)
┌─ MONITORING (горячий список) ────────────────────────────────┐
│ poll 10–30 сек: цена/объём/трейды (DEX Screener pair,        │
│ Birdeye) + LP-события по открытым позициям                   │
└──────────────┬───────────────────────────────────────────────┘
               ▼ trigger_volume AND trigger_price AND gate
        scoring → Telegram-алерт (entry zone, SL, чек-лист)
```

**Источники и их роли (проверены 09.06.2026):**

| Источник | Роль | Цена/лимиты |
|---|---|---|
| DEX Screener API | discovery + базовый мониторинг пар | бесплатно; 60 rpm (profiles/boosts), 300 rpm (pairs/search). В доках заявлен и WebSocket — стабильность публичного WS проверить ⚠️ |
| RugCheck API | Solana security | read без ключа |
| GoPlus API | EVM security | есть бесплатный tier; лимиты проверить ⚠️ |
| honeypot.is API | EVM honeypot-симуляция | публичный API; лимиты проверить ⚠️ |
| Birdeye API | OHLCV (вкл. секундные TF в v3, до 5000 свечей/запрос), trades | платные тарифы от младшего Starter; точные цены смотреть на bds.birdeye.so/pricing ⚠️ |
| Moralis | холдеры EVM+Solana, статистика, timeseries | free tier есть; лимиты проверить ⚠️ |
| GMGN | insider/bundler/sniper/dev-метрики; есть OpenAPI (репо GMGNAI/gmgn-skills: Solana, BSC, Base) | условия доступа к API проверить ⚠️ |
| LunarCrush | X/соцсигнал | от бесплатного тарифа |
| Helius (RPC, webhooks; LaserStream/Yellowstone gRPC) | прямой on-chain стриминг Solana | **не нужен в алерт-режиме**: LaserStream доступен с плана $999/мес — при капитале $1–2k экономически абсурдно. Webhooks/RPC на дешёвых планах — опция для LP-watch |
| Bitquery | исторические данные pump.fun/Solana для бэктеста | платно; объём бесплатного доступа проверить ⚠️ |

Бюджетная конфигурация старта: **$0–50/мес** (DEX Screener + RugCheck + GoPlus + honeypot.is free + минимальный Birdeye или вообще без него на первом этапе). Архитектурное требование: каждый источник за интерфейсом-адаптером (`DataProvider`), чтобы смерть/платность любого API не убивала систему.

### 2.2 Скоринг сигналов и вероятность пробоя

Двухфазная схема — сначала экспертный скор, после накопления исходов — калибровка в вероятность:

```
score = w_vol   * scale(vol_z, 4, 12)            # 0..1
      + w_price * scale(roc_15m, stage.lo, stage.hi)
      + w_part  * scale(unique_buyers_ratio, 1, 5)
      + w_flow  * consec_inflow_windows / 5
      + w_soc   * social_confirm                  # 0/0.5/1
      - sec_penalty                               # из security gate
      - w_late  * late_entry_penalty              # цена уже > +40% за 1ч
# старт: w_vol=0.30 w_price=0.25 w_part=0.20 w_flow=0.15 w_soc=0.10
alert if score >= 0.65          # порог = регулятор частоты алертов
```

Фаза 2 (после ≥200–300 размеченных исходов): логистическая регрессия `P(breakout | features)`, где breakout := исход «+25% раньше, чем −20%, в течение 6ч» (path-resolved). Фичи те же + стадия, сеть, время суток. Веса экспертного скора заменяются выученными. Честная статистика: при WR 35% и n=200 95%-CI ≈ ±6.6 п.п. — раньше 200 исходов перекалибровка бессмысленна.

Outcome tracking: переиспользовать пайплайн `outcomes/pending.json → resolved.csv` из текущего скринера. Разметка по фактическому пути цены (T+1ч/6ч/24ч), не по снапшоту.

### 2.3 Логика входа и выхода (исполнение руками по алерту)

Алерт = не «купи», а торговый план:

```
🔔 ALERT [S1] $TICKER (Solana) score 0.78
ликвидность $84k · mcap $410k · возраст 6д
vol_z 6.2 · 15m +14% · buyers 71 (x4.1) · inflow 4 окна
gate: PASS · RugCheck 12 · LP burned · top10 19% · dev 2%
──────────────────────────────
ENTRY: откат в зону $0.00041–0.00043 (−4..−7% от хая)
       или ретест пробоя $0.00040; impact чек ≤2% на $150
SL:    $0.00034 (−18%, под лоу импульсной базы)
TP:    40% @ +30% · 30% @ +70% · 30% trailing
ВРЕМЯ: план актуален 15 мин
ЧЕК РУКАМИ: протокол раздела 7 (kill-чеки → форензика → план)
```

Правила, зашитые в генератор плана:
- **Не догонять вертикаль**: если цена > +40% за последний час — алерт понижается до «watch», вход только по откату.
- **Сайзинг от ликвидности**: позиция ≤0.5–1% пула (при пуле $50k → ≤$250–500) И ≤ риск-лимита (см. 2.4). Перед входом — проверка price impact (Jupiter quote API возвращает `priceImpactPct`): impact >2% → размер вниз или пропуск.
- **SL структурный, широкий**: под лоу базы импульса, типично −15…−25% для S1. Тот же принцип, что ATR-буфер в текущем скринере: узкие стопы у мемкоинов выносятся рутинной «раскачкой».
- **Выход по затуханию импульса** (любое из): net_buy_ratio <0.45 два окна по 5м · объём <50% пикового окна · accel <0 и lower high на 5m · −20% от пика позиции (trailing). Плюс time stop: импульс не продолжился за 30–60 мин → выход в безубыток/малый минус.
- **Rug-watch по открытой позиции**: LP remove >20% · dev-кошелёк переводит >1% supply на CEX/новые кошельки · unlock <48ч → алерт «ВЫХОД НЕМЕДЛЕННО». Это самый ценный автоматический алерт всей системы.

### 2.4 Управление капиталом

При депозите $1–2k:
- Риск на сделку 1–1.5% депо = $10–30. При SL −20% → позиция $50–150. Нижняя граница экономики: позиция <$80 при издержках за круг ~5% теряет смысл (см. 3.1) → практический размер **$100–250**, риск ~1.5–2.5% на сделку — выше классического, это осознанная плата за порог рентабельности ⚠️.
- ≤2–3 одновременных позиций (мемкоины коррелированы с SOL/BTC — это один риск-фактор, а не диверсификация).
- Дневной стоп −5% депо, недельный −10% → пауза 48ч и разбор журнала.
- Капитал на бирже/в кошельке для этого жанра — отдельный от фьючерсного, ментально списанный в R&D.

### 2.5 Latency и исполнение в алерт-режиме

Бюджет времени: событие on-chain → детекция (polling 10–30с) → скоринг (<1с) → Telegram push (1–3с) → человек открыл терминал и исполнил (20–60с). Итого **1–2 минуты от события до позиции**. Отсюда два следствия:
1. Сигналы должны иметь горизонт жизни ≥10–30 минут (momentum S1/S2). Всё, что решается за секунды (снайпинг S0, первые блоки после миграции), — структурно не ваша игра: там уже сидят боты с ~87% WR и Jito-бандлами.
2. Исполнение — через терминал с MEV-protect: Axiom (комиссия ~0.9%, с рефералкой ~0.7%), GMGN, Photon, BullX (~1%). Slippage выставлять руками 1–3%, никогда «auto/unlimited». Совокупная стоимость круга на Solana-терминалах: ~1% bot fee + 0.1–0.3% priority/Jito + 0.5–2% slippage в каждую сторону.

Если позже включать автоисполнение (фаза 2+): Solana — Jupiter Swap API + Jito-бандлы либо RPC с MEV-protect; EVM — приватные RPC (Flashbots Protect на ETH; для BSC — проверить актуальные private-tx сервисы ⚠️). Но это отдельный проект с кастодиальным риском ключей.

## 3. Оценка прибыльности и метрики

### 3.1 Структура издержек (за круг, Solana через терминал)

| Статья | Диапазон |
|---|---|
| Комиссия терминала (вход+выход) | 1.4–2.0% |
| Slippage (вход+выход) | 1–4% |
| Priority fee / Jito tip | 0.1–0.3% |
| Price impact (при соблюдении лимита ≤1% пула) | 0.5–2% |
| **Итого за круг** | **~3.5–8%, медианно ~5%** |

Сетевые комиссии Solana сами по себе ничтожны (медиана ~$0.004/транзакцию); издержки делают терминал и slippage. Следствия:
- цель сделки <+25% не имеет смысла: половину съедают издержки;
- каждое лишнее «передёргивание» позиции — −5% оборота;
- на BSC/Base структура аналогичная (газ $0.01–0.3), на ETH mainnet газ убивает экономику позиций <$1–2k → ETH исключён.

### 3.2 Честная модель PnL — ⚠️ ОЦЕНКА, не факт

Публичных верифицируемых win-rate статистик для систем этого класса нет. Ниже — расчётная модель от структуры стратегии; реальные параметры узнаются только из собственного датасета (этапы 0–3 roadmap).

Допущения: SL −18% (нетто с издержками ≈ −23%), лесенка TP даёт средний gross-выигрыш ≈ +63% (нетто ≈ +58%), time-stop режет часть лоссов до −5…−10%.

| Сценарий | WR | EV на сделку (нетто, % позиции) |
|---|---|---|
| Пессимистичный | 25% | 0.25·58 − 0.75·23 ≈ **−2.8%** (убыточен) |
| Breakeven | ~28.5% | ≈ 0 |
| Базовый | 33% | ≈ **+3.8%** |
| Хороший | 40% | ≈ **+9.4%** |

Выводы из модели:
- **Edge тонкий и держится на хвостах**: P&L месяца делают 1–3 сделки с +100–300%; медианный месяц около нуля. Психологически это серии из 5–10 лоссов подряд — без журнала и заранее принятых лимитов система бросается ровно перед прибыльным кластером.
- При WR 33%, EV +3.8%, позиции $150 и ~10 качественных сигналах/нед: ≈ $55–60/нед ⚠️ грубая оценка при идеальной дисциплине. На капитале $1–2k это R&D-доходность, не зарплата. Главная ценность этапа — валидированный датасет и система, масштабируемая капиталом позже.
- Max drawdown: при WR ~1/3 серия из 12–15 лоссов на горизонте 500 сделок — ожидаемое событие; при риске 2%/сделку DD 20–30% — норма жанра ⚠️. Закладывать в лимиты и психику заранее.
- Бенчмарк честности: 60% участников рынка мемкоинов в минусе, <3% заработали >$1000 (Dune/BeInCrypto по pump.fun). Цель «стабильно лучше 97% участников» — амбициозная, даже если абсолютные суммы скромные.

### 3.3 Методология бэктеста (по фреймворку backtest-expert)

**Гипотеза (формулировка до теста):** «Токены S1/S2, прошедшие security gate, при vol_z≥4 + roc_15m≥порога + росте уникальных покупателей достигают +25% раньше, чем −20%, в ≥33% случаев в течение 6ч».

**Данные — главная проблема жанра:**
- Survivorship bias смертелен: датасет ОБЯЗАН включать мёртвые и срагованные токены. Готовые price-API отдают преимущественно выживших.
- Источники истории: Bitquery (архивы Solana/pump.fun: трейды, миграции, bonding curve), Birdeye OHLCV (до 5000 свечей/запрос, есть секундные TF в v3) — оба платные/лимитные ⚠️.
- **Primary source = собственный forward-сбор**: с дня 1 логировать ВСЕХ кандидатов discovery (вкл. отвергнутых гейтом) + их исходы. Через 4–6 недель это даст незаменимый чистый датасет с полным набором фич на момент решения.

**Анти-look-ahead (урок short_dist / _resolve_exit):**
- событийный реплей: фичи сигнала в момент t считаются строго по данным ≤ t;
- исходы — path-resolved: идём по свечам/трейдам вперёд и фиксируем, что наступило раньше — TP или SL; внутри одной свечи, задевшей оба уровня, — консервативно считать SL первым;
- никакого «затем цена была X через 6 часов» как замены пути.

**Стресс-набор перед любым выводом:**
- slippage ×1.5–2 от модельного, комиссии по верхней границе;
- sensitivity: каждый порог (vol_z, roc, buyers, score cutoff) ±30% — edge не должен исчезать;
- разбивка по режимам рынка (SOL bull / chop / drawdown), по сетям, по времени суток;
- walk-forward: калибровка на окне 1–2 мес → тест на следующем месяце, скользяще;
- сравнение с базлайнами: «купить любой прошедший гейт токен» и «случайный вход» — скоринг обязан бить оба.

**Verdict-критерии:**
- **Deploy**: n≥300 сигналов, OOS profit factor ≥1.4, EV>0 после стресс-издержек, ни один режим рынка не катастрофичен, sensitivity-плато.
- **Refine**: edge есть, но живёт в узком диапазоне параметров или одном режиме.
- **Abandon**: edge исчезает при 2× slippage или существует только в одном месяце данных. Сворачивать без сожаления — датасет остаётся активом.

## 4. Основные риски

### 4.1 Ложные пробои и рыночный шум

Типовые паттерны манипулированного «импульса» и контрфильтры:

| Паттерн | Признак | Фильтр |
|---|---|---|
| Bundled pump | десятки кошельков покупают в одном/соседних блоках | GMGN bundler rate >25% → reject; проверка однородности размеров |
| Wash trading | объём растёт, уникальные холдеры — нет | требование роста buyers и холдеров вместе с объёмом |
| Paid boost/trending | DEX Screener boost, трендинг-каналы | boost ≠ сигнал (амбивалентен — текущий `boost_watcher.py` это уже показал); вес только при on-chain подтверждении |
| Шиллинг → exit | соц-спайк до/без on-chain потока | social = подтверждение, не триггер (см. 1.3) |
| Одна свеча-выброс | vol_z высокий из-за единичного спайка | медиана+MAD; требование 2–3 последовательных окон подтверждения. Плата: +1–3 мин задержки, выигрыш: кратное снижение false-rate |

Числового порога «сколько ложных пробоев устранимо» в литературе нет ⚠️ — это и есть предмет калибровки на собственных исходах.

### 4.2 MEV / sandwich (в ручном режиме)

Sandwich-атака возможна и на ручной своп в мелком пуле: жёсткий slippage cap 1–3%, MEV-protect режим терминала (Jito-роутинг), крупный вход дробить на 2–3 части. Если транзакция не проходит при честном slippage — это информация (пул токсичен), а не повод поднять slippage до 10%.

### 4.3 Liquidity traps

Риск «вход есть — выхода нет»:
- позиция ≤0.5–1% ликвидности пула — главный механический лимит;
- sell-симуляция (honeypot.is/GoPlus, Jupiter обратный quote) ДО алерта, а не после входа;
- rug-watch по открытым позициям (LP remove, dev-трансферы, unlock <48ч) — см. 2.3;
- token-2022 hooks / изменяемые fee — reject на гейте;
- помнить: ликвидность мемкоина испаряется и без злого умысла — time stop обязателен.

### 4.4 Инфраструктурные

- Смерть/платность любого API → адаптеры источников + деградация функций вместо падения системы.
- Пропуски при polling (всплеск короче интервала) → принять как издержку дизайна: цель не «поймать всё», а «не пропустить устойчивое».
- Rate-limit бан за агрессивный polling → центральный rate-limiter на процесс, не на модуль.
- Ложная уверенность от красивого бэктеста на грязных данных — риск №1 всего проекта (см. 3.3).

## 6. Roadmap с нуля (8–12 недель)

Принцип: **данные собираются с дня 1, деньги рискуются с недели ~8**. Каждый этап имеет gate-критерий; не прошёл — не двигаемся.

**Этап 0 — каркас и сбор (нед. 1–2)**
Discovery-цикл по DEX Screener; схема хранения (кандидаты, фичи, снапшоты, исходы); логирование ВСЕХ кандидатов, включая отвергнутых.
Gate: 7 дней непрерывного сбора без дыр; ≥1000 кандидатов в базе.

**Этап 1 — security gate + детектор (нед. 2–4)**
Интеграция RugCheck/GoPlus/honeypot.is; volume/price/buyers-триггеры; shadow-алерты в отдельный TG-канал (без торговли).
Gate: false-rate гейта на ручной выборке 50 токенов <10% (вручную проверить, что reject'ы — действительно мусор); 20–60 shadow-сигналов/нед.

**Этап 2 — скоринг + outcome tracking (нед. 4–6)**
Композитный скор; разметка исходов T+1ч/6ч/24ч path-resolved (адаптация pending.json/resolved.csv); еженедельный отчёт WR по диапазонам скора.
Gate: ≥150–200 размеченных исходов; монотонность «выше скор → выше WR» видна.

**Этап 3 — бэктест и вердикт (нед. 6–8)**
Калибровка логистической моделью; стресс-набор из 3.3; где возможно — догрузка истории (Bitquery) для проверки на другом периоде.
Gate: вердикт по критериям Deploy/Refine/Abandon. Abandon — тоже результат: датасет и каркас переживут стратегию.

**Этап 4 — микро-лоты (нед. 8–10)**
Торговля руками по алертам, позиции $25–50 (осознанно ниже рентабельности — платим за проверку исполнения); журнал: slippage факт vs модель, latency «алерт→исполнение», расхождение план/факт.
Gate: ≥30 сделок; фактические издержки в пределах модельных ×1.5; дисциплина 100% (ни одной сделки вне алерта).

**Этап 5 — рабочий размер (нед. 10–12+)**
Позиции $100–250 при соблюдении лимитов из 2.4; rug-watch активен; ежемесячный пересмотр порогов walk-forward-процедурой.
Kill-критерии: −10% депо за неделю → стоп и разбор; 3 месяца EV≤0 при n≥150 → Abandon/Refine.

Параллельно с этапа 2: вторая сеть (BSC) — только после того, как Solana-пайплайн стабилен.

## 7. Доскональный разбор монеты перед входом (протокол ручного анализа)

Алерт живёт ~15 минут; протокол рассчитан на **≤5 минут**. Ключевая установка: причина войти уже есть — её нашёл бот. Задача человека — **найти причину НЕ войти**. Вы не аналитик, подтверждающий сделку, вы прокурор, ищущий дисквалификацию. Все пороги ниже — стартовые эвристики ⚠️.

### 7.0 Слой 0 — что уже проверил бот (0 сек, читается из алерта)

Не дублировать руками: honeypot/sell-симуляция, mint/freeze authority, LP lock/burn, tax, top-10/dev/sniper/bundler-проценты, vol_z, buyers, inflow. Руки проверяют то, что автоматике недоступно или даётся плохо: контекст графика, связность кластеров, история дева, источник внимания, фаза движения.

### 7.1 Слой 1 — kill-чеки (≤60 сек). Любой провал = пропуск без обсуждения

1. **Живые продажи.** Лента трейдов (GMGN/DEX Screener) за 5 мин: есть ли УСПЕШНЫЕ продажи обычных кошельков, не только покупки? Поток из одних buy = подозрение на soft-honeypot или гейт, обманутый нестандартным контрактом.
2. **Фаза движения.** Цена от точки зажигания импульса >+50% или от 24ч-лоу >+100% → вы покупаете у тех, кто входил по сигналу. Только лимитка на откат, по рынку — нет. Вертикаль на 1m без единого отката ≥2 мин = не вход.
3. **Liq/MCap.** Ликвидность/mcap <3% → при развороте выход физически невозможен → пропуск. Здоровая зона S1: 5–20%. (>40% тоже странно: либо свежак, либо искусственный пул.)
4. **Биография графика.** Зум-аут на весь период жизни: это первый импульс или N-й цикл «памп → −70%»? Серия пампов с понижающимися хаями = доильный аппарат, пропуск.
5. **Рынок-якорь.** SOL (для Solana-токена) / BTC за последний час: падение >1.5–2% → мемкоин-лонги выключены, алерт игнорируется. Корреляция в риск-офф стремится к 1.
6. **Impact на выход.** Quote на ПРОДАЖУ двойного размера позиции (Jupiter/терминал): impact >4–5% → размер вниз или пропуск. Выходить придётся в слабость, не в силу.

### 7.2 Слой 2 — форензика (2–3 мин)

**Холдеры и кластеры (Bubblemaps + GMGN holders):**
- крупные пузыри, связанные трансферами, = один оператор; его суммарная доля считается как один холдер — пересчитать top-10 с учётом этого;
- кошельки, получившие токены ТРАНСФЕРОМ от дева/ранних (не покупкой), — отложенный слив;
- динамика top-20 прямо сейчас: докупают (хорошо) или раздают на росте (инсайдер выходит в толпу — плохо);
- one-glance-правило: один пузырь ≥⅓ карты = treat as red.

**Дев и его история (GMGN/RugCheck creator):**
- сколько токенов создал этот кошелёк раньше и что с ними: ≥3–5 мёртвых = серийный фабрикант, пропуск;
- движения дева за последние часы: перевод баланса на CEX/свежие кошельки = подготовка выхода;
- фондирование кошелька дева: с CEX — норма; со свежего моста/миксера — warn.

**Кто несёт объём (GMGN traders):**
- top-трейдеры токена: уже фиксируют? массовая фиксация ранних на вашем «раннем» сигнале = стадия позднее, чем кажется;
- smart money / известные KOL-кошельки среди покупателей последнего часа = плюс; их выход = сильный минус;
- серии однотипных сумм с fresh-кошельков = бандлы, объём фальшивый (бот мог недосчитать — глаза надёжнее).

**Источник внимания (≤60 сек, не залипать):**
- найти первоисточник пампа (пост в X/TG). Время поста vs время начала движения on-chain: движение НАЧАЛОСЬ ДО поста = инсайдеры закупились под раздачу — поздно;
- TG-канал: участники vs онлайн (50k членов / 200 онлайн = накрутка), возраст канала, включены ли комментарии;
- X: возраст аккаунта, не переименован ли из старого (фабрика), органика в реплаях vs боты-восторги;
- для S2-«проектов»: календарь анлоков/вестинга — анлок в ближайшие дни = warn.

**Структура графика (фреймворк technical-analyst, 60 сек):**
- HTF-контекст (15m/1h, если возраст позволяет): тренд, ключевые S/R, где ближайшее предложение;
- текущий паттерн: сжатие/флаг после импульсной свечи = вход на пробое флага; третья нога параболы = поздно; ровный канал вверх на падающем объёме = распределение;
- уровни для TP: предыдущий хай, круглые mcap-отметки ($1M/$10M — реальные психологические магниты толпы);
- сформулировать 2–4 сценария с весами, например: 50% продолжение после флага → TP-лесенка; 30% ретест зоны пробоя (−10%) → там добор не нужен, просто held SL; 20% разворот → SL. Если сценарий «вверх» не набирает ≥50% — пропуск.

### 7.3 Слой 3 — письменный план ДО входа (60 сек)

```
ТИКЕР/CA: ______          сеть: ____  стадия: S_
вход:   зона ______–______ (лимитка, не маркет)
размер: $____  (≤1% пула; sell-impact ×2 ≤4–5%; риск ≤2% депо)
SL:     ______ (−__%, под лоу базы; шире «качелей»)
инвалидация идеи (не цены): ____________________
TP1 40% @ ____   TP2 30% @ ____   trail 30% (momentum-decay)
time stop: ____ мин   rug-watch: ON
```
Поле «инвалидация идеи» — главное: что должно произойти, чтобы сетап умер независимо от цены (выход smart money, разворот net inflow, слив дева). Не заполняется уверенно любое поле → сделки нет.

Жёлтые: средняя история дева (1–2 старых токена), мутный соц-источник, серые кластеры (связи есть, но <10% supply), поздняя фаза (+30–50%), фиксация части топ-трейдеров. Красные: серийный дев, раздача инсайдеров в рост, движение до поста, один пузырь ≥⅓ карты, sell-лента пустая.

Каждый разбор логировать (1 строка: тикер, решение, флаги, причина) — включая пропуски. Это вторая половина датасета: через 100 разборов станет видно, какие ручные флаги реально предсказывают исход, а какие — суеверие.

### 7.5 Типовые ошибки ручного входа

- Маркет-вход в вертикаль вместо лимитки в зоне отката (плата: −3–7% сразу).
- Усреднение вниз — в этом жанре запрещено полностью: мемкоин без momentum не «дешёвый», он мёртвый.
- Перенос SL «ещё чуть-чуть» — структурный SL двигается только за структурой (выше), никогда ниже.
- Доливка после TP1 «раз пошло» — ломает математику лесенки, превращает зафиксированную прибыль обратно в риск.
- Вход по алерту во время падения SOL/BTC (kill-чек 5 существует, но рука тянется).
- Разбор >3 алертов подряд без паузы: усталость решений — измеримая утечка WR; после 3 подряд — перерыв 30 мин.
- Торговля без записанного плана: «подержу ещё» и «выйду на глаз» — это не план, это казино.
