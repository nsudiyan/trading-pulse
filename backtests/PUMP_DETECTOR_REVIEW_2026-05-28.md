# Ревью pump_detector — слабые места и план (2026-05-28)

**Метод:** 6 агентов (скоринг/выходы/режим/данные/активация + синтез), привязка к коду, отсев overfit/разоблачённого. Полный лог: task `wgnunnq2m`. Ревью независимо ВОСПРОИЗВЕЛО объёмный edge (stack lift 2.39 на held-out test n=5280) — A1 подтверждён сторонне.

## 🔴 КРИТИЧНО — состояние LIVE прямо сейчас

1. **Бот шлёт невычитанные сигналы как GO.** `pump_detector.py:1591`: `if _act not in ("GO","FAIL_OPEN")` → **FAIL_OPEN отправляется.** Claude-фильтр в fail-open (кредиты кончились) → главный гейт качества молча ВЫКЛЮЧЕН, сигналы идут в TG.
2. **Это совпало с анти-предиктивным гейтом.** `CONVICTION_MIN_SCORE=85` (пластырь «слать только сильнейшие»), НО собственная калибровка бота (`claude_realtime_filter.py:257-261`): score 50-70 → WR 73.7%, score 120+ → WR 50% («ловушка confluence»). Аддитивный score анти-предиктивен на верхах → гейт 85 **отбирает худшую по WR зону.** Согласуется со старым выводом (score>120 → 31.5%).
3. **Нет kill-switch на памп/раг пути.** Audit-mode только в `screener.py:6457`; у pump_detector нет проверки `streak_monitor.is_audit_mode()`. Просадка/серия лоссов НЕ останавливает; рестарт обнуляет дневной счётчик (он in-memory).
4. **WR измеряется по сделке, которую никто не берёт.** `sl_pct` клампится в [1,6]% (`claude_realtime_filter.py:742`), промпт толкает SL 2-4%, а валидированный широкий стоп ~8% **недостижим**. Шумовой −3% стоп метит выживаемых движенцов как LOSS → 3 несогласованных определения WIN/LOSS портят метрику.

## Прочие слабые места (с привязкой)
- Самореферентный объём: `vol_avg10`(candles[-12:-2]) пересекается с V1-окном спайка [-13:-1] на 10/12 → `vol_ratio_1h≈1.0` по построению, порог >1.0 почти всегда true (`pump_detector.py:924,1247-1250`). Валидированный lift live НЕ переносится.
- Все валидированные факторы — мёртвый код (`USE_VALIDATED_V1=False:262`; btc_cascade lift 5.12 тоже под флагом в rug_detector:527). Live держится на невалидированном аддитивном confluence.
- Clamp `min(score,130)`(1320) обходится: skew(+20/−15, 1458-1469) и orderbook(±10, 1503-1544) меняют score ПОСЛЕ клампа, dex_adj добавляется в watch-loop(2008) → гейт на неограниченной сумме.
- Коррелированный двойной счёт: OI учтён 5× (gate+30m+4h+Binance-OI+skew), CVD 3×, funding 3× — один и тот же рид надувает confluence.
- `btc_4h` как прокси `btc_trend_1h` (горизонт-mismatch); held-out re-run: btc_trend для ПАМПОВ плоский (2.33 vs 2.46) → удалить для лонгов.
- Мёртвый код: `_liq_cluster_score`(538) определён, не вызывается; `STRONG_SOLO_SCORE=80`(56) не используется → solo-паттерны проходят на 35 без confluence.
